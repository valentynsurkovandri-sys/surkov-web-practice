## 2. Мета, аудиторія, сценарії

**Мета сайту:** допомогти покупцям швидко знайти й зберегти вироби ручної роботи українських майстрів у потрібному ціновому діапазоні та оформити замовлення.

**Цільова аудиторія:**
- люди 20–40 років, які шукають унікальний подарунок (переважно заходять зі смартфона);
- поціновувачі українського handmade та етнодекору;
- невеликі майстри, які хочуть представити свої вироби.

**3 ключові сценарії:**
1. **Пошук подарунка в межах бюджету.** Користувач відкриває каталог, задає ціну «від–до» (наприклад, 300–800 грн), переглядає картки, відкриває деталі товару.
2. **Збереження товарів на потім.** Користувач додає кілька товарів у список бажань (♡), пізніше відкриває сторінку «Список бажань» і порівнює їх.
3. **Замовлення / запитання майстру.** Користувач заповнює форму замовлення на сторінці контактів, отримує повідомлення про успішне надсилання.

## 3. Призначення

Публічний вебсайт-каталог із клієнтською частиною на React (Vite) і власним REST API на Node.js (Express). Сайт показує товари, дає змогу фільтрувати їх за ціною та категорією, зберігати у список бажань і надсилати заявку на замовлення.

## 4. Структура сторінок (карта сайту)

- Головна (/)
  - Каталог (/catalog)
    - Деталі товару (/items/:id)
  - Список бажань (/wishlist)
  - Замовлення / Контакти (/contact)
  - Сторінка 404 (*)

| Сторінка | Вміст |
|----------|-------|
| Головна | Банер, популярні категорії, 4–8 нових товарів, переваги магазину |
| Каталог | Сітка карток, фільтр за ціною (від–до + повзунок), фільтр за категорією, сортування, пошук |
| Деталі товару | Галерея фото, назва, ціна, опис, матеріали, майстер, кнопки «♡ У список бажань» і «Замовити» |
| Список бажань | Збережені товари, загальна сума, видалення, перехід до замовлення |
| Замовлення / Контакти | Форма (ім'я, email, телефон, товар, кількість, спосіб доставки, коментар, згода), контакти, мапа |
| 404 | Повідомлення та посилання на головну й каталог |

## 5. Функціональні вимоги

1. **ФВ-1.** Перегляд каталогу товарів у вигляді карток (фото, назва, ціна, кнопка ♡).
2. **ФВ-2.** Фільтр за ціною: поля «від» і «до» та повзунок; фільтр застосовується без перезавантаження сторінки. *(обов'язкова функція)*
3. **ФВ-3.** Список бажань: додавання та видалення товару кнопкою ♡ з картки й сторінки деталей; дані зберігаються в localStorage і не зникають після перезавантаження. *(обов'язкова функція)*
4. **ФВ-4.** Сторінка «Список бажань» з переліком збережених товарів, лічильником у шапці та загальною сумою.
5. **ФВ-5.** Фільтр за категорією (прикраси, кераміка, текстиль, декор, іграшки) та сортування (ціна ↑/↓, новинки).
6. **ФВ-6.** Пошук товарів за назвою з debounce 300 мс.
7. **ФВ-7.** Сторінка деталей товару за адресою `/items/:id` з даними з API.
8. **ФВ-8.** Форма замовлення з валідацією на клієнті та на сервері (обов'язкові поля, email, телефон у форматі +380XXXXXXXXX).
9. **ФВ-9.** REST API з CRUD для товарів: `GET/POST /api/items`, `GET/PUT/DELETE /api/items/:id`, а також `POST /api/contact`.
10. **ФВ-10.** Перемикач світлої/темної теми зі збереженням вибору.
11. **ФВ-11.** Обробка станів «завантаження», «помилка», «нічого не знайдено» (наприклад, якщо у вибраному діапазоні цін немає товарів).

## 6. Нефункціональні вимоги

- **Адаптивність:** верстка mobile-first; коректне відображення на ширинах 360, 768 і 1280 px.
- **Швидкодія:** Lighthouse (mobile) Performance ≥ 90; зображення у WebP, lazy loading; LCP < 2,5 с, CLS < 0,1.
- **Доступність:** WCAG 2.1 AA, контраст тексту ≥ 4,5:1, повна навігація з клавіатури, видимий фокус, alt для всіх зображень; Lighthouse Accessibility ≥ 90.
- **SEO:** унікальні title/description, sitemap.xml, robots.txt; Lighthouse SEO ≥ 90.
- **Сумісність:** останні версії Chrome, Firefox, Safari, Edge.
- **Безпека:** серверна валідація всіх вхідних даних, секрети лише в `.env`.
- **Мова інтерфейсу:** українська.

### Список бажань (Wishlist) — на клієнті

Зберігається в localStorage під ключем `wishlist` як масив id товарів: `[3, 7, 12]`.

## 9. Взаємодія клієнта і сервера

1. React-клієнт у браузері робить запит `GET /api/items?minPrice=300&maxPrice=800` до Express-API.
2. Сервер читає дані з `items.json`, фільтрує й повертає JSON зі статусом 200.
3. Клієнт відмальовує картки; список бажань клієнт зберігає локально, без звернення до сервера.
4. Під час надсилання форми клієнт робить `POST /api/contact`; сервер перевіряє дані й повертає 201 (успіх) або 400 (перелік помилок).
